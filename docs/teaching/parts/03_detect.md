## 专题三|人脸检测：在图里把脸框出来|从 Haar 到 RetinaFace / SCRFD，锚点、多尺度、NMS {#t3|三 检测}

> 检测是整条流水线的第一步：输入一张任意大小的照片，输出每张脸的方框 (x1, y1, x2, y2)、置信度，以及 5 个关键点。后面的对齐、识别、特效全都依赖它。本项目用 SCRFD-10G（RetinaFace 的高效改进版），在 WIDER FACE 上评测。

### 知识要点 {#t3-s1}

**1. 检测在做什么。** 分类问题回答"这张图是什么"，检测要同时回答"在哪里"和"是什么"。对人脸检测来说，"是什么"只有一类（脸 / 不是脸），所以难点全在"在哪里"：脸可能大到占满屏幕，也可能小到只有 10 个像素；可能侧着、戴口罩、被手挡住、在暗处。 {#t3-k1}

**2. 三代方法。** 第一代 Haar 级联（Viola-Jones，2001）：手工设计"眼睛比脸颊暗、鼻梁比两侧亮"这类黑白矩形特征，用一串越来越严格的分类器层层筛选窗口，速度快但侧脸、遮挡就失灵（`tools/opencv_basics.py` 里可以跑它对比）。第二代 MTCNN（2016）：三个小网络 P-Net / R-Net / O-Net 级联，先粗筛候选框再逐级精修，同时输出 5 个关键点。第三代单阶段检测器 RetinaFace（2020）/ SCRFD（2021）：一个网络一次前向，在多个尺度的特征图上"每个位置都问一遍有没有脸"，精度和速度都最好，本项目用的就是它。 {#t3-k2}

**3. 锚点（anchor）。** 把特征图上的每个格子映射回原图，就是原图上一个等间距的网格点，这个点叫锚点。网络不需要"凭空"猜框，只需要回答：这个锚点附近有没有脸？如果有，脸的上下左右四条边离这个锚点各有多远？这就把"找框"这个开放问题变成了"每个格子做一道填空题"。SCRFD 每个位置放 2 个锚点，步长（stride）分别是 8、16、32 像素。 {#t3-k3}

类比：像在操场上每隔 8 米站一个同学，每个人只负责报告"我脚下有没有人脸、脸的边界离我多远"。小脸靠密的那排同学（stride 8），大脸靠稀的那排（stride 32）。

**4. 多尺度：FPN 特征金字塔。** 卷积网络越深，特征图越小，每个格子"看到"的原图范围（感受野）越大、语义越强，但细节越少。浅层特征图大、细节多但"不懂"什么是脸。FPN 把深层的语义特征上采样后加回浅层，让每一层都"既看得清又看得懂"。stride 8 的那层负责小脸，stride 32 的那层负责大脸。 {#t3-k4}

**5. 输出与解码。** 对每个锚点，网络输出 1 个分数、4 个距离、10 个关键点偏移，全部以 stride 为单位。设锚点中心为 (cx, cy)，网络输出距离 (l, t, r, b)，则 {#t3-k5}

```latex
\begin{aligned}
x_1 &= c_x - l\cdot s, & y_1 &= c_y - t\cdot s,\\
x_2 &= c_x + r\cdot s, & y_2 &= c_y + b\cdot s,\\
\text{关键点}_k &= (c_x + \Delta x_k\cdot s,\; c_y + \Delta y_k\cdot s), & k&=1,\dots,5
\end{aligned}
```

预测"相对锚点的距离"而不是"绝对坐标"，是因为卷积是平移不变的：同一个卷积核在左上角和右下角做同样的计算，它只能输出"相对于我自己位置"的量。

**6. NMS 非极大值抑制。** 一张脸周围的好几个锚点都会说"我这有脸"，得到一堆高度重叠的框。NMS 的做法：按分数从高到低排序，取出最高分的框保留下来，删掉所有和它 IoU 超过阈值（0.4）的框，对剩下的重复这个过程。IoU（交并比）衡量两个框的重叠程度： {#t3-k6}

```latex
\mathrm{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}=\frac{|A\cap B|}{|A|+|B|-|A\cap B|}\in[0,1]
```

**7. letterbox 预处理。** 网络输入固定 640×640，而照片可能是 1280×720。直接拉伸会把脸压扁，检测器没见过扁脸。做法是等比例缩放到能放进 640×640 的最大尺寸，空白处补黑边；检测完把坐标除以缩放比例就回到了原图。 {#t3-k7}

易错点：OpenCV 读图是 BGR 顺序、形状 (高, 宽, 3)；网络要 RGB、形状 (1, 3, 高, 宽)、像素归一化成 (x − 127.5)/128。`cv2.dnn.blobFromImage` 一行完成这三件事，任何一步漏掉结果都会变差但不会报错，最难查。

### 代码精读 {#t3-s2}

#### 代码 1|facevision/detector.py：从图片到人脸框 {#t3-c1}

整个检测器只有一个 ONNX 模型文件 `det_10g.onnx`，网络本身不需要我们写；我们要写的是前处理（letterbox + 归一化）和后处理（解码 + NMS），这两部分决定了结果对不对。

```python
def detect(self, img, input_size=None, max_num=0, conf_thresh=None):
    det_img, scale = self._letterbox(img, input_size)        # 1. 等比缩放 + 补黑边
    blob = cv2.dnn.blobFromImage(det_img, 1.0 / 128, input_size,
                                 (127.5, 127.5, 127.5), swapRB=True)   # 2. 归一化, BGR->RGB, HWC->NCHW
    outs = self.session.run(self.output_names, {self.input_name: blob})  # 3. 网络前向: 9 个输出
    return self.postprocess(outs, blob.shape[2:], scale, img.shape, max_num, conf_thresh)
```

9 个输出 = 3 种步长 ×（分数、框、关键点）。后处理对每种步长做同样的事：

```python
for idx, stride in enumerate(self.strides):            # 8, 16, 32
    scores = outs[idx].reshape(-1)                      # 每个锚点 1 个分数
    bbox_pred = outs[idx + 3].reshape(-1, 4) * stride   # 4 个距离, 乘回像素单位
    kps_pred = outs[idx + 6].reshape(-1, 10) * stride   # 5 个关键点偏移
    centers = self._anchor_centers(in_h // stride, in_w // stride, stride)
    pos = np.where(scores >= conf_thresh)[0]            # 只解码"可能是脸"的锚点
    boxes = distance2bbox(centers[pos], bbox_pred[pos])
    kps = distance2kps(centers[pos], kps_pred[pos])
```

锚点中心就是网格坐标乘步长，每个位置重复 2 次（2 个锚点）：

```python
ys, xs = np.mgrid[:h, :w]
centers = (np.stack([xs, ys], axis=-1) * stride).reshape(-1, 2)
centers = np.repeat(centers, 2, axis=0)
```

最后把所有步长的结果拼起来、除以 scale 回到原图坐标、按分数排序、NMS。`max_num=1` 时会在剩下的框里挑"面积大且靠近图像中心"的那一个，LFW 评测就是这样选主角的。

#### 代码 2|批量 GPU 版 SCRFDBatch：一个反直觉的 bug {#t3-c2}

预处理 20 万张 CelebA 时，CPU 逐张检测太慢，于是用 onnx2torch 把 ONNX 转成 PyTorch，在 Intel 核显上一次跑 64 张。第一版直接把输出 reshape 成 (64, -1, k) 按 batch 切开，结果全错。原因是 SCRFD 导出时用的是 `permute(2, 3, 0, 1)`：输出按 (高, 宽, batch, 锚点) 的顺序展平，batch 维夹在中间。正确的切法：

```python
per = [o.reshape(-1, b, 2, o.shape[-1])[:, i].reshape(-1, o.shape[-1]) for o in outs]
```

验算：修正后与单张 CPU 版逐点比较，关键点最大误差 1.5×10⁻⁵ 像素；256×256 输入下批量核显版 5.3 ms/张（单张 CPU 版约 14 ms），而且把 CPU 让给了其他任务。这个例子说明：拿到别人的模型，一定要用"已知正确的实现"逐元素对拍，而不是看着"差不多能跑"就用。

### 例题 {#t3-s3}

#### 例题 1|IoU 怎么算 {#t3-e1}

**框 A = (10, 10, 50, 50)，框 B = (30, 30, 70, 70)，求 IoU。**

交集是两个框重叠的部分：左上角取两者较大的 (30, 30)，右下角取两者较小的 (50, 50)，所以交集是 20×20。每个框面积 40×40 = 1600。

```latex
\mathrm{IoU}=\frac{20\times 20}{1600+1600-400}=\frac{400}{2800}=\boxed{0.143}
```

结论：两个框看起来"有一大块重叠"，IoU 却只有 0.14。IoU 是一个很严格的指标，0.5 已经算"框对了"。

#### 例题 2|锚点解码 {#t3-e2}

**stride = 16 的特征图上，第 3 行第 5 列的锚点，网络输出距离 (2.5, 3, 2.5, 4)，求原图上的框。**

锚点中心 = (5×16, 3×16) = (80, 48)。距离乘步长得像素：(40, 48, 40, 64)。

```latex
(x_1,y_1,x_2,y_2)=(80-40,\;48-48,\;80+40,\;48+64)=\boxed{(40,\,0,\,120,\,112)}
```

这张脸宽 80、高 112 像素，用 stride 16 的锚点负责它正合适（距离值在 2～4 之间，网络最容易学的范围）。

#### 例题 3|NMS 手算 {#t3-e3}

**4 个候选框（x1, y1, x2, y2, 分数）：① (100,100,200,200, 0.95)，② (110,105,205,210, 0.90)，③ (300,120,380,210, 0.80)，④ (105,95,195,190, 0.60)。NMS 阈值 0.4，保留哪些？**

第一轮：最高分是 ①，保留。算它和其余框的 IoU：与 ② 为 0.748，与 ③ 为 0（不相交），与 ④ 为 0.775。② 和 ④ 都超过 0.4，删掉。

第二轮：剩下 ③，保留。

```latex
\text{保留}=\boxed{\text{框 1 和框 3}}\quad\text{(两张不同的脸)}
```

易错点：阈值太低（如 0.2）会把两张挨得很近的真脸（合影里并排的人）错删一张；太高（如 0.8）又会留下重复框。人脸检测常用 0.4。

#### 例题 4|letterbox 坐标还原 {#t3-e4}

**1280×720 的图送进 640×640 的检测器，在网络输入上检测到框 (100, 50, 200, 180)，原图上是哪里？**

宽高比 720/1280 = 0.5625 小于 1，宽度先撑满：缩放比 scale = 640/1280 = 0.5，缩放后 640×360，下面 280 行补黑边。黑边补在右下，左上角没有平移，所以直接除以 scale：

```latex
(100,50,200,180)\div 0.5=\boxed{(200,\,100,\,400,\,360)}
```

#### 例题 5|一张 LFW 图为什么检测失败：补边技巧 {#t3-e5}

**LFW 评测中有一对图被判错，原因是 Nabil_Shaath_0002.jpg 选错了脸（选成了背景里的人）。主角的脸占了大半个画面，但右边被画面边缘切掉一块。怎么修？**

分析：检测器训练时见过的脸几乎都是完整的，对"被切掉一块的脸"打分很低（0.36，低于 0.5 的阈值），于是只剩背景里的小脸。做法是检测前给图片四周补一圈黑边（边长的 25%），让脸完整地落在画面里：补边后主角的脸置信度升到 0.78，成为最大、最居中的那张，被正确选中。关键点坐标最后减去补边宽度即可回到原图。

结论：这是一个通用的工程技巧，不针对某张图。加上后 LFW 的检测阶段 7701 张图全部检出，见专题七的错误分析。
